# LiteLLM 人格模拟与界面验证

## 研究范围与当前证据

第一轮用五种行为人格假设做认知走查，回答「用户可能找不到什么、误解什么、错误后如何恢复」，产出待验证的前台与后台需求。人格不是访谈结果，模型意见不是用户偏好统计。

当前工具只向 LiteLLM 提交人工审核的静态界面控件清单，不启动浏览器、不操作账户、不执行付款、删除、成员修改。控件来自 `re8ch/user-hub` 的 `public/index.html`，版本与路径保存在 `research/ux/scenarios.json`。静态 HTML 包含隐藏区块，因此所有控件的运行时可见性均为 **未知**。模型提出的步骤不能当成已经点击过的步骤。

实际推理尚未执行：需要批准的 HTTPS 网关入口、模型别名和经批准方式注入的短期凭证；不从本地平台配置提取密钥。没有这些绑定时只运行 dry-run，不能发布模拟结论。实际浏览器执行也处于阻塞状态：当前工作环境未启用浏览器操作能力。不能用静态源码替代浏览器运行证据。

## 最小执行方式

从本研究 worktree 执行，Python 标准库即可，无需安装 SDK：

```sh
python3 -m unittest discover -s research/ux -p 'test_*.py'
python3 research/ux/simulate.py --dry-run --limit 5 --output /tmp/identity-ux-dry-run.json
```

dry-run 验证输入与报告链路，报告标记 `status=dry-run`、`browser_executed=false`，每个场景 `not-executed`。它不验证凭证、网关可用性或模型行为。

批准的运行环境需注入 `LITELLM_BASE_URL`（以 `/v1` 结尾的网关基地址）、`LITELLM_MODEL` 和 `LITELLM_API_KEY`。不得把值填入仓库、命令行参数或研究报告。随后运行：

```sh
python3 research/ux/simulate.py --limit 1 --output /tmp/identity-ux-pilot.json
```

先检查一个场景的结果，再显式运行 `--limit 5`。脚本每场景一次请求，无重试；最多五个请求，每次 45 秒网络超时、1200 个最大输出 token、256 KB 响应上限。拒绝 HTTP 与重定向，避免把授权头带往其他目的地。输出文件独占创建，不覆盖旧证据。token 限制不等同货币预算，应使用已有网关对该身份的限额；报告只保留模型用量，不复制凭证或上游错误正文。错误停止本轮且退出码非零。

模型必须返回拟议步骤、控件 ID、摩擦假设、前台需要、后台需要和下一步验证方法。未知控件引用、缺少验证方法或无效 JSON 均算失败，不自动修补为「通过」。模型正文仍是非可信内容；发布到 Project 前由研究人员复核。结果只表示模拟已执行，不表示体验达标。

## 从模拟进入实际界面操作

第二轮由浏览器执行者在隔离测试环境执行用例，沿用同一人格目标与用例 ID：

1. 使用活跃 `Re8ch` 测试组织成员；另设普通成员、组织管理员、平台操作员，禁止用 Admin 成员代替 tenant 成员。
2. 记录测试版本、角色、当前组织、viewport、语言、无敏感数据的截图与可访问树。只有这个快照能证明控件当时可见。
3. 把模型建议转成单个可审核操作；执行者校验目标确实存在、操作在本用例范围内，再执行。付款、停用、成员权限和注销只在明确准备的测试夹具执行。
4. 每一步记录实际动作、观察到的状态、接口结果类别和恢复动作；后端验收使用测试断言，不让模型自评代替授权隔离、幂等与审计检查。
5. 每个断言给出通过、失败、阻塞或未执行。模型步数和拟议步骤不能用来计算任务完成率。
6. 再组织真实用户任务测试，检验发现是否真实存在。跨人格重复的模型意见仍只算一类合成信号，不算多位受访者的独立证据。

## Project 记录格式

每条发现包含 `SIM-xx`、关联用例 ID、源码 SHA、输入摘要、模型别名、运行时间、控件 ID、摩擦假设、前台改动候选、后台能力候选、严重性、下一步验证、证据级别与负责人。原始输出留在受限研究存储，Project 仅存脱敏发现及引用。不能上传真实账号、Cookie、请求 token 或 MFA 信息。

第一轮场景：非技术新用户进入系统；多组织管理员管理成员；共享设备用户授权与退出；用户和运营协作处理数据请求；团队成员解释消费与用量。完整成功/失败标准由 `use-cases.md` 和 `v1-experience-baseline.md` 管理。

## 为什么需要这个脚本

GitHub Projects 可管理研究任务与证据，Actions 可执行受限验证，但二者本身不提供基于人格和 UI 清单的模型认知走查。此脚本仅补充一次性研究请求与结果契约，不承担凭证同步、部署规划、轮询或控制器职责，不在 GitOps runtime 中部署研究工具。真实浏览器执行器尚未实现，应作为独立、可评审的后续交付，而不能把离线走查包装成端到端测试。

接口依据：[LiteLLM 官方快速开始](https://docs.litellm.ai/docs/proxy/docker_quick_start)、[官方 API 参考](https://docs.litellm.ai/api-reference)，核对日期 2026-10-30；使用 OpenAI 兼容 `POST /v1/chat/completions`。
