# 用户系统 V1 稳定体验基线

状态：研究提案，尚未通过发布验收。日期：2026-10-30。

本轮浏览器交互工具在当前 Work 环境不可用，未执行界面操作或生产体验验证。主任务通过 GitHub API 确认仓库为公开仓库（`private=false`）；README 的 private 描述不作为权限证据。本目录只存通用研究规范与公开代码引用，不存租户内部数据、原始研究记录、凭据或运行时拓扑。

本轮目标是让用户知道“我是谁、正在以哪个组织的身份做什么、结果如何、失败后怎样继续”。功能是否进入 V1 由关键任务的成功和可恢复性决定，不以入口数量决定。本文件中的人格、阈值和范围均为待验证假设；没有采访数据或线上运行证据支持用户偏好、成功率或稳定性结论。

## 行为人格假设

| 人格 | 行为与任务 | 关键风险 | 需要研究的信号 |
| --- | --- | --- | --- |
| P-N 首次使用者 | 从应用进入，希望完成登录并回到原任务 | 误建重复账号、不理解身份提供商 | 能否解释关联与新建的区别 |
| P-R 回访用户 | 跨设备使用，管理会话、安全及数据申请 | 被锁出账号、误解注销状态 | 能否恢复任务、理解状态与下一步 |
| P-O 多组织负责人 | 切换团队、管理成员和最小权限 | 误判目标组织或影响范围 | 操作前后能否正确识别组织与角色 |
| P-D 应用连接者/开发者 | 连接应用服务并查看授权和消费 | 不理解 scope、归属或费用含义 | 能否解释权限与用量/实际消费区别 |
| P-S 平台支持人员 | 处理账号问题、导出/注销申请 | 把 Admin 权限当作租户资格、无证据完成 | 是否核验组织、版本与实际履约 |

人格按行为分组，不按年龄、国籍或性格刻板印象设定。移动设备、键盘/读屏和低带宽是横跨人格的测试条件。真实研究后合并或拆分人格，不先假定这些分组覆盖全部用户。

## V1 范围与前后台责任

| 关键旅程 | 前台用户能力 | 管理后台能力 | 服务端/运行保障 | V1 决策 |
| --- | --- | --- | --- | --- |
| 登录与回到任务 | 可用登录方式、登录状态、取消和重试、保留应用授权上下文 | 定位失败类别，不读取用户凭据 | PKCE、会话验证、提供商可用性、受限回跳 | 必须；仅展示已验证可用的方式 |
| 账户资料与身份关联 | 资料、已验证联系方式、明确关联/新建选择 | 支持排查重复与冲突，不绕过归属证明 | 统一账号 ID、一次性票据、原账号校验 | 必须；冲突不得静默合并 |
| 应用授权 | 应用、当前身份、范围、允许/拒绝 | 审阅授权策略和异常 | 校验授权请求、有效会话和回调 | 必须；明确普通授权与敏感操作 step-up 的区别 |
| 当前组织 | 明示个人/团队及当前资源组织、切换结果 | 组织目录与成员管理分离于资源上下文 | 同组织有效成员校验、服务端授权和数据隔离 | 必须；Re8ch 与 Re8ch Admin 分别验收 |
| 成员与权限 | 普通用户理解本人访问权限 | 最小角色、成员变更、结果与审计定位 | 后端鉴权、禁止越权、敏感变更验证 | 必须；高级组织移动可延后 |
| 会话与账号安全 | 当前设备、登录方式、二次验证状态和可恢复错误 | 支持安全事件定位，操作有审计 | 会话失效、验证因子状态、恢复策略 | 必须；未验证恢复能力不得宣称完整 |
| 服务与账单理解 | 服务归属、用量、实际扣减、钱包/订单的清晰区分 | 查询异常并交由对应服务处理 | 权限过滤、数据新鲜度、状态一致性 | 只读闭环必须；购买另设门槛 |
| 隐私请求 | 身份快照、申请、取消、状态和用户可见说明 | 开始处理、说明拒绝、记录带证据的完成 | 版本冲突控制、审计、履约证据权限 | 必须；申请不是即时删除 |

不在本轮承诺新建全套 API 密钥控制台、通用资源编排器或平台迁移。只有用户任务证据支持时才进入候选。真实支付、成员破坏性变更和账户删除不得由模拟人格在生产执行；使用隔离测试数据、预览或只读任务。

## 源码支持的首批研究问题

1. **授权说明冲突（S）**：`README.md` 一处写普通应用授权不要求 MFA，另一处写 OAuth Server 授权必须已绑定且验证 TOTP。`public/app.js` 的 `renderConsent` / `decideConsent` 展示范围并提交决定，局部函数没有 TOTP 门槛。不能据此推断服务端策略；需分别验证实际客户端路径及服务端策略，然后统一文档与界面。
2. **组织双重上下文（S→H）**：`renderOrganizationCenter` 同时建立 `directory-scope` 和 `active-organization`；`selectActiveOrganization` 成功后提示后续 MCP/资源请求使用新组织。两者实现存在，但用户是否能区分是 H。应安排“查看 A 目录，同时当前资源组织为 B”的任务，观察用户对后续操作归属的判断。
3. **授权范围可理解性（S→H）**：`renderConsent` 将 `details.scope` 直接放入 `consent-scopes`，缺省为 `openid`。非技术用户能否解释授权内容需要验证，候选改进是展示用户能理解的权限说明；不能将默认显示理解成服务端实际授权。
4. **错误恢复语境（S→H）**：`decideConsent` 出错转入通用 `error` 区域，`public/index.html` 标题为“登录暂时不可用”。授权失败可能被理解成登录失败，需模拟过期请求、拒绝及网络故障并检验恢复路径。
5. **账单概念并列（S→H）**：`public/index.html` 同页呈现购买 Credits、实际消费、资源用量、历史服务 Credits、历史购买记录。并列有源码证据，“用户混淆”尚无证据；任务应要求用户区分记录用量与实际扣减，而非直接要求重设计。
6. **隐私状态语义（S）**：`README.md` 明确身份快照不含产品数据/账单/凭据，申请流程不执行真正删除。界面和支持话术必须保持此边界；验收涵盖取消竞争、版本冲突、拒绝说明与完成证据权限。
7. **登录入口是否有效（S→T 待办）**：`public/index.html` 有多种提供商入口；入口存在不能证明后端配置、提供商审核和回跳链路可用。逐项验证并记录环境，未验证项不计入发布通过率。

## 可量化发布门槛（提案，不是当前结果）

| 门槛 | 计算和测试方式 | 通过要求 |
| --- | --- | --- |
| 核心正确性 | 所有 P0 用例在目标构建、支持浏览器和规定角色矩阵运行，保留步骤/断言/结果 | 100% 通过；阻塞、跳过均不计通过；连续两轮无回归 |
| 组织隔离 | Re8ch、Re8ch Admin、两个独立测试租户及停用成员，覆盖读写和切换后的陈旧状态 | 越权成功数为 0；不能只验证隐藏按钮 |
| 错误恢复 | 过期会话、过期票据、网络中断、403、版本冲突各有明确断言 | 无静默成功、无重复敏感提交；保留可重试或重新开始入口 |
| 用户理解 | 真实用户完成后复述当前账号/组织、授权意义、隐私请求状态 | 关键概念每项至少 5 人观察；至少 4/5 正确；任一严重归属误解阻断发布 |
| 任务完成 | 每项关键旅程至少 5 名匹配行为的用户；无主持人操作提示 | 每项至少 4/5 独立完成；单列帮助完成与失败，不外推总体成功率 |
| 无障碍与布局 | 核心任务键盘完成，焦点可见，错误被读屏宣告；移动 390px 与桌面 1440px | 无核心控件不可达、焦点丢失或遮挡；对照任务逐项记录 |
| 性能与反馈 | 固定测试网络和设备，至少 30 次非外部身份提供商页面任务；记录起止点 | 本地操作反馈 p95 ≤ 1 秒；第一屏可操作 p95 ≤ 3 秒；外部依赖单列而不藏入平均值 |
| 发布证据 | 签名 PR、GitHub Actions、部署制品版本和真实运行核验关联 | 都齐备才发布“稳定”；合并 PR 不等于部署完成 |

阈值由产品负责人评审后冻结；不足样本或未知运行状态记为未通过。模拟输出不能填补真实用户门槛，也不能作为隔离或安全通过证据。

## 真实用户验证与迭代

第一轮招募 8–12 位覆盖上述行为的参与者，让同一人完成多个合适任务，使每项核心任务获得至少 5 次观察。该样本用于发现问题，不用于宣称总体市场比例。先取得录制同意，使用专用测试账号和数据；保存脱敏观察记录，原始录像限制访问，不上传 Git。

主持人给目标而非点击路径：“从应用进入后继续原任务”“确认下一次操作属于哪个组织”“解释此处的用量是否等于扣费”。记录任务结果、耗时、回退、求助、原话（仅真实观察）、环境与构建。访谈问实际经历，避免诱导参与者认同模型建议。对最严重问题安排修复后的同条件复测。

GitHub Project 的每条发现保留“假设→模拟线索→测试复现→真实用户验证→范围决定→发布验证”证据链。建议记录负责人、人格、旅程、优先级、证据等级和产品归属；实现任务转到负责仓库，研究卡链接实现 PR。拒绝或延后也写理由，不能为达到“完成”而删除反例。

LiteLLM 人格模拟负责快速暴露遗漏、表达不清和候选恢复路径；必须记录模型/版本、提示、输入界面版本、运行环境、实际工具动作与观察。没有浏览器工具轨迹的文本推演标为“脚本走查”，不写“已操作界面”。最终 V1 稳定性由上述 T/U/P 证据共同支撑。
